# Data

The training and test data, built from sources pinned in `configs/data/sources.yaml`. The rules (which rows are
excluded, how the splits are drawn) live in [`protocol.md`](../protocol.md); this file says what the data is and how
many rows each part has.

## Sources

- `critique`: the ThinkGuard critique release (luka-group/ThinkGuard, `beavertails_critiques_aug.json`). BeaverTails
  prompt-response pairs, each with a teacher critique that gives a safety label, categories and an explanation. The
  training data.
- `beavertails_30k_train`: BeaverTails 30k train (PKU-Alignment). Not normalized on its own: it supplies the human
  gold label of each critique row with the same prompt-response pair.
- `beavertails_30k_test`: BeaverTails 30k test, prompt-response pairs with a human safety label and categories.
- `toxicchat_0124_test`: ToxicChat 0124 test (lmsys), user prompts with a toxicity label.
- `openai_moderation`: OpenAI's moderation API release, prompts with per-category labels.
- `wildguardtest`: WildGuardMix test (allenai, gated), prompt-response pairs with a response harm label.

## Pipeline

Run from the repo root, in this order:

1. `python -m thinkguard.data.normalize`: loads each source at its pinned revision and writes one `Example` per row
   to `data/interim/<source>.jsonl` (not in git).
2. `python -m thinkguard.data.filter_train`: sets `exclusion_reason` on the critique rows, in
   `data/interim/critique_filtered.jsonl`.
3. `python -m thinkguard.data.manifest`: freezes every split as `data/manifests/<split>.json` (in git): its
   `example_id`s and the sha256 of its rows. `thinkguard.data.manifest.load_split` loads a split and raises if its rows
   changed.
4. `python -m thinkguard.data.audit`: writes `reports/data_audit.md`.

`python -m thinkguard.data.verify_readme` checks the numbers below against the data, and `--write` regenerates them.
CI runs it with `--committed-only`, which checks only the source revisions and split row counts, because
`data/interim` is not in git.
